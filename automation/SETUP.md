# Clinora — Offline Deployment Guide

Clinora is a fully offline clinic management system. The entire stack runs on a single local PC. No internet is required after the initial setup.

---

## What's in this folder

| File | Purpose |
|---|---|
| `setup.bat` | **Run once** — installs all dependencies, configures the database, creates a desktop shortcut |
| `start.bat` | **Daily use** — starts the backend + frontend servers and opens the browser |
| `stop.bat` | Stops all Clinora servers cleanly |
| `startup-prompt.vbs` | Pop-up script that Windows runs at login |
| `install-startup.bat` | Registers the pop-up so it appears on every Windows login |
| `uninstall-startup.bat` | Removes the startup pop-up |
| `clinora.config.bat` | Auto-generated by `setup.bat` — stores server IP and ports |
| `clinora.ico` | (Optional) Place your `.ico` file here to use as the desktop shortcut icon |

---

## Prerequisites — install these before running setup

| Software | Minimum version | Download |
|---|---|---|
| **PHP** | 8.3+ (Thread Safe x64) | https://windows.php.net/download/ |
| **Composer** | latest | https://getcomposer.org/Composer-Setup.exe |
| **Node.js** | 20 LTS | https://nodejs.org/ |

### PHP setup on Windows
1. Download the **Thread Safe** x64 ZIP from https://windows.php.net/download/
2. Extract to `C:\php`
3. Copy `php.ini-production` → `php.ini` inside `C:\php`
4. Open `php.ini` and enable these extensions (remove the leading `;`):
   ```
   extension=fileinfo
   extension=mbstring
   extension=openssl
   extension=pdo_sqlite
   extension=sqlite3
   extension=zip
   ```
5. Add `C:\php` to your Windows **System PATH**
   - Search → "Edit environment variables" → System variables → Path → New → `C:\php`
6. Restart any open terminal / command prompt and run `php --version` to verify

## One-time setup

> **Run this once** when setting up on a new PC, or after copying the project to a new location.

1. Open the `automation\` folder
2. Right-click `setup.bat` → **Run as administrator**
3. Follow the prompts — the script will:
   - Verify PHP, Composer, and Node.js
   - Detect the PC's LAN IP address
   - Configure `backend/.env` and `frontend/.env` automatically
   - Install all PHP and Node dependencies
   - Create the SQLite database and run migrations
   - Create a **"Start Clinora"** shortcut on the desktop

> The setup takes 2–5 minutes on the first run.

## Daily operation

### Start Clinora

Double-click **"Start Clinora"** on the desktop.

This starts two background processes:
- **Backend** — Laravel API server on port `8000`
- **Frontend** — React application on port `5173`

A browser window opens automatically at `http://localhost:5173`.

### Access from other PCs on the LAN

Other computers connected to the same network (LAN cable or Wi-Fi) can open:

```
http://<server-IP>:5173
```

The server's LAN IP is shown every time `start.bat` runs. It is also saved in `automation\clinora.config.bat`.

### Stop Clinora

Run `automation\stop.bat` — or close the two minimised "Clinora Backend" and "Clinora Frontend" command windows.

## Auto-start with Windows

To show a prompt every time the PC is turned on or logged into:

1. Run `automation\install-startup.bat`
2. From the next login onwards, a dialog will appear asking:
   > *"Start Clinora Clinic Management System?"*
3. Click **Yes** to start, **No** to skip

To remove the auto-start prompt, run `automation\uninstall-startup.bat`.

## Multiple simultaneous logins — Doctor + Pharmacist

Clinora supports the doctor and pharmacist being logged in **at the same time on the same PC**, as long as they use **different browsers**.

| User | Browser |
|---|---|
| **Doctor** | Google Chrome |
| **Pharmacist** | Microsoft Edge (or Mozilla Firefox) |

**Why different browsers?**
Each browser keeps its own login session completely separate. If both users logged into the same browser, the second login would replace the first, effectively logging out the other person.

On different PCs on the LAN, both users can use any browser — their sessions are already isolated.

## Changing the server PC (new machine or new IP)

If the PC gets a different IP address (e.g. after a router change), re-run `setup.bat`. It will detect the new IP and update the configuration automatically.

If you just want to update the IP manually:
1. Open `frontend/.env` and change `VITE_API_URL` to the new IP
2. Open `backend/.env` and change `APP_URL` and `SANCTUM_STATEFUL_DOMAINS` to the new IP
3. Restart the servers (`stop.bat` then `start.bat`)

## Troubleshooting

### "PHP not found" after installing PHP
- Close all Command Prompt / PowerShell windows and reopen them
- Run `php --version` to confirm the PATH is working

### Browser shows "This site can't be reached"
- The servers may not have finished starting. Wait 10 seconds and refresh.
- Check that the Backend and Frontend windows are still open (minimised in the taskbar).
- Run `stop.bat` then `start.bat` again.

### "Port already in use" errors
- Run `stop.bat` first to clear any old processes, then `start.bat` again.

### Doctor and pharmacist logging each other out
- They must use **different browsers**. See the [Multiple simultaneous logins](#multiple-simultaneous-logins--doctor--pharmacist) section above.

### Pharmacist PC cannot connect (from LAN)
- Make sure the server PC's **Windows Firewall** allows inbound connections on ports `8000` and `5173`:
  1. Search → "Windows Defender Firewall with Advanced Security"
  2. Inbound Rules → New Rule → Port → TCP → `8000, 5173` → Allow the connection
- Check that both PCs are on the same network/VLAN.

### Database issues / lost data
- The database lives at `backend/database/database.sqlite`
- **Back up this file regularly** — it contains all patient, prescription, and visit records.
- To reset the database completely: delete `database.sqlite` and run `php artisan migrate` from the `backend/` folder.

### Re-running setup after code updates
- Run `setup.bat` again. It is safe to re-run — it skips steps already completed and updates configuration.

1. Place your `clinora.ico` file in the `automation/` folder
2. Re-run `setup.bat` (or manually update the shortcut: right-click → Properties → Change Icon)
